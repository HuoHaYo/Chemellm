# 对话工具调用的持久恢复

2026-10-20。对话执行器已通过独立云端真实模型中断控制例；显式研究任务的操作及历史证据见[STUDY_WORKFLOW.md](STUDY_WORKFLOW.md)。

## 使用

服务重启时，将未收到确认的运行中调用标为`unknown`，保留原模型调用批次和输入。当前项目有未知调用时，开始新对话执行和继续任务均被拦截。选择对应项目，在“中断调用待核对”查看实际输入及候选计算，打开“核对并确认处置”，填写核对者和说明：

- **采用已有记录：** 核对中断前已有计算和文件后选择记录。服务检查同项目、同工具、调用开始后生成、经schema验证的实际业务输入完全一致；拒绝失败/不可用结果、缺失/越界文件和已标记过期文件。采用后保留原计算/产物ID及文件，不重新执行工具。
- **确认重新执行：** 核对没有可用结果或明确承担再执行后保存确认。原中断尝试保留为`retry_approved`，新尝试链接旧尝试并使用原保存输入，计入原预算。

处置不会自动开始模型。确认后点击“继续此任务”，先完成原批次余项，再请求模型。已确认调用不重放，确实尚未开始的余项可继续。处置事件保存核对者、说明、时间、调用/尝试ID；页面保留“中断处置记录”。这是执行结果核对，不等于科学或工程审核；当前共享工作台也不能认证核对者身份。

接口为`GET /api/runs/{id}`及`POST /api/runs/{id}/tool-attempts/{attempt_id}/reconcile`，后者接受`decision: adopt|retry`、`reviewer`、`notes`及采用时的`calculation_id`。继续沿用服务鉴权。浏览器无需编辑数据库或访问隐藏接口。

## 持久性与预算

`app/run_recovery.py`复用既有`runs.result`，无需数据库结构迁移。完整assistant批次和待执行队列在调用前提交，每次尝试的输入/哈希、调用ID、子任务、次数和时间基线在副作用前提交；确认结果、模型tool回复及队列出队一起保存。终态任务不会再次分派。取消中的未返回工具也须核对；旧记录依据未答复调用或未匹配`tool_start`保守重建unknown，不能假定未执行。

累计次数包含中断和重试；重启不重置时间预算。无法证明实际运行时间时，从调用开始至启动恢复的经过时间按保守上界计费到时间预算，包含停机时间，并保存`recovery_elapsed_upper_bound_seconds`；这不是精确CPU时间或模型费用统计。重复启动不重复计入同一窗口。费用预算、硬性终止、跨进程队列与一般性恰好执行一次语义仍待验收。

正常输入/领域`ValueError`沿用422及失败ID修复协议；有副作用工具的非领域异常或确认保存失败按`UncertainToolError`返回409并要求处置，显式研究任务也保留该不确定状态。这依赖当前领域错误在前置校验阶段拒绝的约定，不能推断任意后端异常都无副作用。按实际失败ID与子任务关联修复，不同任务的一次成功不能关闭旧失败。
