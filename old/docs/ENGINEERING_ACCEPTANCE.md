# 一轮对话全套工程交付验收

2026-10-21。平台主目标见[RESEARCH_PLATFORM_GOAL.md](RESEARCH_PLATFORM_GOAL.md)。当前第一关是实际DeepSeek经平台完成赛题全套文件的一轮交付；赛题用于验收通用工程能力。下列是完整验收标准，尚无整包通过记录。按用户指定顺序，下一次整包对话只能在31项必需与4项条件计分材料逐项门槛全部通过后启动。

## 输入和执行

从新项目开始，一次用户输入附原始题目和必要资料，保存附件哈希、约束、平台源码版本、模型配置和预算。不能预置本次设计的成品文件、答案或计算结果作为平台产出；通用模板、可追溯数据库与工具允许使用。

平台内部可多次请求模型、检索、计算、校核和修复，自动维护任务依赖并持续到整包交付。正常运行不依赖用户逐项调用工具、反复点继续或人工补件。题目允许自行决定的设计选择由平台完成调研和论证。缺少无法自行取得的关键外部输入时如实报告，保留失败和缺项；不能靠隐藏追问、人工改文件或事后改变输入宣布本次一轮验收通过。

最终用户获得成果目录、各文件预览/下载、完整压缩包、要求到文件/页码及校核证据的索引。自动校核可以在内部重复进行；最终确认依靠保存的文件和检查证据，不由生成模型一句“完成”决定。

## 逐项测试程序与当前结果

`app/competition.py`为35个稳定编码各记录原PDF精确源文片段；`tests/test_competition_source_coverage.py`逐条验证片段都出现在工作区原题PDF，并通过平台`document_extract`、`document_read`、`engineering_requirements`工具对35项实际上传/提取/逐字绑定。此组件测试通过只证明原题条目覆盖与来源追溯链路，不证明任何工程成果正确。

对实际项目包逐项运行只读审核器：

```powershell
python scripts/competition_item_gate.py --bundle <项目成果包.zip> --output <逐项结果.json>
```

它逐项检查要求来源引句及哈希、成果映射、原件和格式自动检查、打包字节哈希、本轮成功工具生成轨迹及单轮运行条件；独立记录专业审核状态。原题中期刊字数/格式、AutoCAD 2004与gbcbig.shx、可运行模拟/软件源文件、便携机现场打开等条件同时作为共享输出门槛；审核器不能自行证明科学正确或专家批准。

当前首轮冻结失败运行`282e073372c64a319885214c7b461881`的逐项结果为`0/35`，证据在`data/qa/engineering-delivery/282e073372c64a319885214c7b461881/item-gate-baseline.json`。源PDF字节哈希及35组原文片段匹配通过，35项均有成果计划映射；但没有源文绑定，自动原件/格式/内容检查没有任何一项通过，审核状态均为missing。PFD/P&ID及厂区/布置DXF明确仍为方案级，缺少目标CAD实际打开/字体/视觉核验；三维STEP未生成，Icarus和PV Elite源文件未生成，流程模拟原生运行未验证。原始运行是失败基线，未用来宣称修订后平台通过，也未因代码修改而重跑；新平台目前没有运行第二轮整包对话。

## 实施优先级

先建立统一设计依据及要求到成果的对应关系，贯通完整流程/优化、设备及公用工程、安全环保/经济、PFD/P&ID及布置和三维原生文件，再连接自主编排与全套生成/校核。优先修复整包阻断项，可按依赖并行推进工程模块；既有可靠性回归继续维护。大规模保留集、研究消融和微调不作为第一关前置门槛。

首轮通过后更换原料、规模、体系或任务，检查复用与退化，再按工程师常见工作扩展验收。单一赛题通过不代表全部通用工程能力达成。
